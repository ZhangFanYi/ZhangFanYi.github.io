## 概述

具身智能模型的适配与优化是我司我部门今年6月以来需求明显增长的新业务 部门安排我和大凯长期关注并完成相关工作 与此同时 也和训练组的同事互通有无 讨论具身智能模型的适配与优化思路

### 一、适配
适配的方案是统一的 拉取官方代码仓后 删除toml文件中nv相关的包库以及所有海光适配的包 然后在海光的基础镜像的基础上一键安装 最后补全海光版本的包即可 根据开箱测试中遇到的报错进行代码仓的修改或包版本的调整即可

### 二、优化
具身智能模型的优化有两个特点 既有**普遍方法** 又**没有普遍方法** 这两面特点体现了具身智能模型本身的特点

**普遍方法** 
1. 进行**优化器融合** AdwamW换为AdamW_fused 对于开箱trace中优化器耗时占比大的模型很有效果 比如GR00T模型等

2. channel last来**修改卷积算子layout** 因为具身智能模型处理的任务的特殊性 几乎都有视觉 所以这一方法也比较普遍 在ACT Dreamzero Lingbot-vla模型优化中都有使用 效果取决于卷积算子的占比
   
3. 全局或者局部**开启融合** 这取决于模型的结构以及输入 比如GR00T模型中就只在Action-head中进行融合 对于Lingbot-va模型 全局融合会触发重编译 方法是提取三个热点算子为独立函数并分别进行融合
  
4. **Gemm调优 & miopen调优** 这类优化方法取决于模型的trace中各部分的占比 这也并不是具身智能模型的优化“专利” 取决于trace文件中各部分的表现
   
5. 模型的主干模型分析是很重要的 比如对于以wan为主干的Dreamzero Fastwam以及Lingbot-va 以及以Qwen系列vl模型为主干的GR00T和Lingbot-vla模型 这些都可以参考**主干模型的优化**

**非普遍方法**

1. **面向架构**：具身智能模型的种类和架构各不相同 从方法论的角度来说 我们的优化在某些场景下可以概括为对官方实现方法缺陷的优化 比如Dreamzero Lingbot-va/vla模型 这就需要对模型训练中内在的行为和代码实现逻辑
进行详细的分析 发现缺陷后进行优化

2. **面向显存和训练框架**：除了对模型自身训练的各项行为进行分析和修改 对不同背景下的模型训练也有不同的操作空间 比如有些模型官方推荐的训练框架是面向平民级小显存的卡 对于显存和卡的特点 我们可以尝试不同的训练框架 
在FSDP/DDP/Deepspeed不同stage中进行选择和分析 与此同时 训练框架和显存带来的可操作空间比如 梯度检查点是否开启 梯度累积的步数 是否有必要/能不能开启offload 怎样实现overlap等 都是要考虑的部分

3. **面向数据集和并发**：对于不同的数据集 需要关心以下几点 动态or静态（包括bs是否固定 sequence-lenth是否固定 有无padding等） 这些都影响模型在训练时的行为 要去探索在不同情况下有无优化的方法
   比如Dreamzero模型的优化 消除FA的重复缓存 仅针对固定 batch_size + 固定 sequence_length + 无 padding这个输入才能生效 否则每次都要重建 无法复用缓存 该优化方案就无效
